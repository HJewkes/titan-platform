Refuse math that may store into a command-rebinding parameter (`commands`, `BASH_CMDS`, `functions`, `dis_functions`, `nameddirs`), as `e='commands[y]=0'; shift "$e"` does in zsh: a shift count, `let` operand, `(( ))` body, `$(( ))` or `$[ ]` body, and an array subscript are all evaluated as arithmetic, which assigns. A literal store (`let 'commands[y]=0'`, `(( commands[y] = 0 ))`) is refused, and so is a run-time piece in those places that may expand to one. An fd-variable redirect into a rebinding parameter (`{BASH_CMDS[y]}>f`) is refused too. The names come from one list shared with `PROTECTED`.

The shell expands each run-time piece of a math text before it parses the math, so a text passes only when every piece can yield nothing but a number or trusted text:

- Numbers: `$#`, `$?`, `$$`, `$!`, `${#x}`, `${#a[@]}`, zsh `$+x`, nested `$(( ))`, a `16#ff` base, and the output of a command substitution or backquote that prints only digits, run with literal arguments on a line that rebinds none of them: `date +FORMAT` with digit directives only, `wc -l/-c/-w/-m` reading its input (also at the end of a pipe), `grep -c` over at most one file, GNU `stat -c` with numeric directives, `nproc`, `id -u/-g/-G`, `tput cols/lines/colors`, `seq`, `git rev-list --count`, and `du -s… | cut -f1`. A function named like one of these, an alias, `hash`, `eval` or `source`, a `PATH` change or a nameref on the line voids that.
- A name, bare or `$name`/`${name}`/`${name:-digits}`, is followed to every text the line writes there, wherever on the line the write sits, so a later write in a loop or after a function's definition counts. A number written there (digits, a `$(( ))`, a counted substitution, a `for` over digits) is safe. A `$name` is spliced into the text around it, so its value must also be digits (`x='[y]=0'; (( commands$x ))` is refused).
- A name the line never writes, and that the shell does not set on its own, holds the Bash tool's environment, which the line cannot set, so it is trusted in both forms (`echo $(( $(date +%s) - $start ))`, `(( i < n ))`). So are the positional parameters, which the harness passes none of, and the shell's counters (`SECONDS`, `RANDOM`, `EPOCHSECONDS`, `LINENO`).
- Refused: a name the line sets from a file or a command that may print anything (`n=$(cat f)`, `read -r n < f`), a name the shell sets itself unless the line wrote a number there (`_`, `REPLY`, `OPTARG`, `MAPFILE`, `MATCH`, `BASH_REMATCH`, zsh `reply` and `match`), any name once the line runs text the guard does not read (`source`, run-time `eval`, a run-time command word, a run-time name slot, a nameref, `BASH_ENV`), the positional parameters once the line may set them (`set --`, a call of its own function with a word that is not digits, zsh `argv=…`, a nested shell's arguments), and any other expansion (`${!x}`, `${x/a/b}`, `$'…'`, a math text over 1024 characters). A script the line runs trusts neither its environment nor its arguments.

File contents in math (`echo $(( $(cat count) + 1 ))`, `read -r n < count.txt; echo $((n+1))`) stay refused: one call can write `commands[ls]=0` into the file and a later call read it into math, which the guard cannot see across calls. The parity corpus now lists those two lines as refused on purpose.

Math is read in every place a shell evaluates it inside words and redirects: a redirect target (`: > f$(( $e ))`), an unquoted heredoc body, a substring offset or length (`${x:$e}`, `${x:0:$e}`, read whole even when it holds a subscript, `${b:commands[y]+=0}`), a descriptor variable's subscript, and each element of a compound array assignment (a `[KEY]=` key and any expansion in a later element: `a=([BASH_CMDS[y]=0]=1)`, `a=(x $(( commands[y]=0 )))`), through one list the hooked-parameter reader shares. An `(( ))` body is read as one text, so a store the lexer splits across words or a `<`/`>` it reads as a redirect is seen. An element assignment's subscript is math however much of it is quoted (`a['commands[y]=0']=1`), and so is a quoted assignment argument to a declarer (`declare 'a[commands[y]=0]=1'`).

Accepted false positives: a declarer word used as a plain argument before an element-shaped word (`echo declare 'a[commands[y]=0]=1'`); math over a command the list above does not name (`$(( $(echo 5) ))`); any math on a line that also sources a file or runs run-time `eval` text.

Not covered here: numeric `[[ -eq ]]` operands, `declare -i` values and quoted name arguments to name-taking builtins (`unset 'a[$e]'`).
