Add `securitySliceFlag` and `SECURITY_SLICE_LINES` (400) to flag oversize security or guard-area slices (TP-2395 a). The `generated` set now also leaves out changesets, `packages/*/api/*.d.ts` reports and `.codewatch/dead-exports.json`, so `changedLineCount` and the `large` touch no longer count that churn; a PR sized only by it may now class `standard`. `pnpm-lock.yaml` and snapshots stay counted, since a hand edit there changes what runs.

Add a `dependency` touch, STRICT like `security`, so a PR that changes `pnpm-lock.yaml`, `pnpm-workspace.yaml` or any `package.json` classes `g10` at any size. `touchesDependency(files, rules?)` is exported, and `ReviewerFacts.dependencyTouch` lets a caller that sizes reviewers itself apply the same rule. `ClassRules.dependency` is a new required field (a minor bump under 0.x): a caller that builds its own `ClassRules` must add it.
