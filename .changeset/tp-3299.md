A `g10-review` or `g10-adversary` release no longer refuses Shepherd's own land-time merge-up just because the release runs before the step has recorded it. GitHub shows the update-branch merge seconds before the `update-branch` step records the head as Shepherd's own. If the run's own update-branch step is still running, `shepherd release` now waits up to 60 seconds for that record, then reads the PR again and applies the same clean merge-up proof. If the step is still running after the wait, the release is refused with exit 75 and the caller retries. A head the step did not record as its own, a tree that is not the clean merge-tree, and a push that lands during the wait are all still refused.
