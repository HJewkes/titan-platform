Read a script the line writes from the line as well as the disk, and refuse one the line writes in a way the guard cannot follow. Each redirect gets one effect from a single table: it reads only, writes stdout the guard reproduces, writes a file it does not reproduce, or writes a file it cannot name. Any operator the table does not name counts as a write it cannot name. A file stdout reaches (`>`, `>|`, `>>`, `&>`, `&>>`, `>&`, every one of them, as zsh's MULTIOS copies stdout to each) gains the text of a `cat` heredoc or here-string, `echo` or `printf` whose output is literal, so a push or merge in it is denied when the same line then runs it with `.`, `source`, `bash` or `sh`. A write only adds a reading and never replaces what the file held, since it may sit behind `&&`, in a body that never runs, in the background or under noclobber; an append adds each earlier reading with the text after it, keeping the newline `echo` and a here-string end with. A write whose text the guard does not reproduce (`curl … > f`, `print`, zsh's NULLCMD, a group, a pipe into `cat`), or that goes through another fd (`2> f`, `9> f`, zsh's `11> f`), `<>`, or `<&` to a file, leaves the file untracked. A write to a target only known at run time, or to zsh's `>!`/`>>!`/`&>!`/`>&!` spellings, leaves every file untracked. Running a script from an untracked file, or from one the line left more than 16 readings of, refuses the line with a reason that says to run the script in its own command. A file nothing runs, such as a PR body built with appends or a log, is never refused.
