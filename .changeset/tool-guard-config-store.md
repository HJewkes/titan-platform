"@titan-design/tool-guard": patch
---

tool-guard guards the fleet config store as permission config (TP-3584). A write by any tool or shell form to the materialized coordinator document (`~/.config/titan-coordinator/` and `~/Library/Preferences/titan-coordinator/`), or to the console's owner state (`lan.token`, `owner-actions/` and `config/` under `~/.local/state/titan-console/`), now classifies as `authority-config`. So do `titan-console login-link` and `token rotate`, under the new spelling `bash.config.console-owner-auth`. They are matched as the console receives them: through any wrapper, with a quoted `"token rotate"` read as its two words, or as the console's CLI script under node or tsx, resolved from the command's directory. The spelling also covers `config import`, which seeds the store's first revision, ahead of the console verb that adds it; `config compare-tree`, which only reads, is left alone. Reads of the same paths, and the console's other verbs, still pass. The state directory itself is guarded by its exact path, so removing, moving or copying over it is refused while its inbox and rounds stay writable. A wrapper or runner option that starts the command in another directory (`env -C`, `sudo -D`, `pnpm --filter`/`-C`/`-r`, `npm --prefix`/`-w`, `yarn` and `bun --cwd`) now marks the command (`movesDir`), so a relative console script it runs is still matched. A hard link of a guarded config path (`ln` without `-s`, `cp -l`/`--link`) counts as a write of it. ln's `-s` counts only before its first operand and before `--`, so `ln -- doc -s` is a hard link and refused; and a node or tsx entry is resolved as node resolves it (`dist/cli` runs `dist/cli.js`), with a `-r`/`--require`/`--import` preload, eval text loading the CLI, or a stdin script read as running the console.
