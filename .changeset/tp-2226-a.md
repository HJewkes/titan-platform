`shepherd register` now places the G10 hold itself when it starts a new run for a PR, recorded as a Shepherd hold event: `g10-adversary` for an authority, policy or security touch (a `security` kind counts), otherwise `g10-review` for over 400 changed lines, a file with no line counts, or a store migration (factory's `store-migrations.ts`, `*-migration*.ts`, `*-store.ts` and Shepherd's `store.ts`, `events.ts` and `train.ts` count as one). Shepherd's merge-policy files (`g10-*.ts`, `adversary-*.ts`, `merge-evidence-gate.ts`, `task-kind.ts`, `registration-hold.ts`) count as a policy touch. A file list Shepherd cannot read whole, from an API error or a list past GitHub's cap, fails closed to `g10-adversary`. The G10 hold stacks on any hold the run already has, so that hold gates again once the G10 hold is released; a `g10-review` hold over another class goes in as `g10-adversary`, since only an adversary hold keeps a second hold under it. The hold is a compare-and-swap retried on a fresh read of the run, so a hold placed while the file list is read stands under it. A repeat registration, or a restart whose events already carry a G10 hold, is left as it is. The register output names the hold.
