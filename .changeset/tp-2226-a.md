`shepherd register` now places the G10 hold itself when it starts a new run for a PR, recorded as a Shepherd hold event: `g10-adversary` for an authority, policy or security touch (a `security` kind counts), otherwise `g10-review` for over 400 changed lines, a file with no line counts, or a store migration (factory's `store-migrations.ts`, `*-migration*.ts` and `*-store.ts` count as one). A file list Shepherd cannot read whole, from an API error or a list past GitHub's cap, fails closed to `g10-adversary`. A run already held, a repeat registration, or a restart whose events already carry a G10 hold is left as it is, and a hold placed while the file list is read stands. The register output names the hold.
