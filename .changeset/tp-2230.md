Splice the literal output of a substitution into the word that `eval` or a shell's `-c` runs, where the substitution sits. The spliced text is read in addition to the text without it, so a wrong model of the output (`printf '%d' '#'` prints `0`) can add a denial but never hide one. A push or merge reached through `eval "$(cat <<'E' … E)"`, a cat here-string, `echo`, `printf` or a backquote, including the arithmetic form `eval "$(cat <<'E' $((X)) E)"` and output spliced into a longer word (`eval "git $(echo push) origin HEAD:main"`), is now denied. Output that lands as data, such as `eval "echo $(echo git push …)"`, is not. Output is worked out under bash's and zsh's `echo` and `printf` rules, and each shell's spliced text is read on its own, so a push that only one of them prints is denied: zsh's `echo - …` drops the `-` that bash prints, and bash counts `printf` width and precision in bytes where zsh counts characters. An `echo` or `printf` with a backslash, or an unquoted heredoc that expands anything, splices in nothing. An unquoted heredoc's escapes are read as the shell reduces them. Substitutions whose output is only known at run time (`eval "$(ssh-agent -s)"`) are unchanged. Text that splicing adds is charged to a budget of four characters per character of the line, so nested `eval "$(…);…"` cannot double the work at every level; a line past it is denied unchecked.
