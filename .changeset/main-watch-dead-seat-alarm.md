Serve's main CI watch now logs a `main CI watch ALARM` error, at startup and again whenever the set changes, for each seat its own send route can pick (for a run registered now, and for a merge no seat maps to) that no connected agent-chat session holds. A `detached` seat counts as dead, as the send cannot reach it. A roster that cannot be read skips the check with one warning. Before this, a send to a dead seat failed and was retried quietly every sweep, so no seat heard about a red main.
