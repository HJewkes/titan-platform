A stacked PR whose fix-proof judged its parent branch no longer merges into main on that read after GitHub retargets it with the same head (TP-4259). Shepherd's merge guard gates every decision but a deny when the MERGE's `proofBase` or merge facts are not on the base being decided, so a mechanical MRG-AU gate becomes a `shepherd-merge-guard/no-facts` gate that no coordinator may resolve; a record without `proofBase` is judged on the base its review read the evidence on. Before deciding, land reads the head's fix-proof again on the decided base through the review's own `sh-fix-proof` read and judge (step `sh-fix-proof:<head>@<base>`); only a clean standing or the owner's waiver clears the gate, and any other read gates with its reason. A registration store, registration or head branch that cannot be read now makes the fix-proof read an `error`, not `skipped`, so a transient read failure never stands as a clean proof. A skipped fix-proof judge never counts as a run. fix-proof.yml now also runs on an `edited` event that changes the base, so the retarget starts a run on main; any other edit skips every job in a concurrency group of its own, so it cancels nothing.
