Add `bumpConsumers(host, services, { registry, regen })`. For each behind seat-book consumer it opens one PR on `shepherd/bump-consumers-<hash>`: the raised `@titan-design/*` specifiers plus the lockfile `regen` rewrote, written through the contents API with each file's expected blob. The PR body lists each `name: old → new` and each left-alone pair. Shepherd registers the PR once under the consumer seat's own policy. An open bump PR is checked for before any tree read. It is registered if it is not yet, even when the repo now plans as current or its read fails, and nothing new opens. A closed PR on the same branch is never reopened. Only a PR whose head is in the consumer repo itself counts as the sweep's: a fork PR under a bump branch name is never registered, and one holding the planned branch is refused. A bump branch that already exists with no PR is refused, not reused. A failed regen creates no branch. `registerConsumerBump` registers a PR only when three things hold: its head is in the repo, it is on a `shepherd/bump-consumers-*` branch, and every file it changes is a `package.json`, `pnpm-lock.yaml` or `package-lock.json` modified in place. G10 then classes the registration, so a manifest on a guarded path is held. Nothing calls it yet.
