On a red main, Shepherd now reruns the failed jobs at the red sha once per freeze episode (`sh-main-rerun`, decision 525). If every red job comes back green in Shepherd's own rerun, the repo thaws at the red sha. The rerun runs alongside `sh-spawn-fixer`, so a deterministic red never waits on it, and after a thaw the fixer keeps working the flake task. The fixer brief tells a flaky-test fix that changes only tests to register `--kind test-only` with no mutation spec. A rerun someone else started never counts; the rerun is read with every attempt kept (`checkRunAttempts`), since GitHub's default listing shows only a job's latest attempt. The thaw re-judges main at the red sha first, so a check still running at the red or a red required context from another app keeps the repo frozen, and it holds only while the episode's red sha is still the one rerun. Before the thaw, the episode's fix task becomes a flake task: both runs' ids and URLs, the job names, the failing tests and an error excerpt are appended, the task is tagged `flake` and reopened if it was done, and its `done_when` asks for a root-cause fix, not a retry, a timeout bump or a quarantine. The filed `done_when` is replaced with `force`, which active-work requires, and the notes go last. If the task cannot be updated, the repo stays frozen, and an active-work refusal (`FixTaskRefused`) ends the step at once instead of being retried as an outage. A failing test that already thawed main this way within 24 hours stays frozen as before. The fix-task port gains an optional `markFlake`.

`fileFixTask` no longer replaces an episode's fixer or fix task with a standing fixer from an earlier red. A fixer the episode gained while the standing fixer was looked up keeps its freeze exemption.
