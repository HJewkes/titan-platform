# titan-platform

A multi-agent software factory, and the shared packages it is built from. The repo holds
<!-- generated:package-count start -->62<!-- generated:package-count end --> reusable `@titan-design/*` packages arranged as a strict acyclic DAG, plus the products
composed thinly on top of them. Shared concerns that grew independently in brain, active-work,
codewatch, and the session-miner get extracted here one package at a time, and each old repo
keeps running on the published packages until its capability is rebuilt here.

## The main products

- **Factory and Shepherd** (`products/factory`): code-driven software-factory workflows.
  Shepherd takes a registered pull request through CI to its merge. Guides:
  [Factory](https://hjewkes.github.io/titan-platform/guides/factory) and
  [Shepherd](https://hjewkes.github.io/titan-platform/guides/shepherd).
- **Session miner** (`products/session-miner`): indexes every Claude Code transcript into a
  session graph, searches it, and clusters its recurring failures. Guide:
  [Session miner](https://hjewkes.github.io/titan-platform/guides/session-miner).
- **codewatch** (`apps/codewatch`): a layered code report, from the big picture down to any
  file or symbol. Guide: [Code report](https://hjewkes.github.io/titan-platform/guides/codewatch).
- **Console** (`apps/console`): one read-only console over the local agent and work sources.
  See [apps/console/README.md](apps/console/README.md).
- **Retrieval eval** (`products/retrieval-eval`): the harness retrieval decisions are judged
  against. Guide: [Retrieval eval](https://hjewkes.github.io/titan-platform/guides/retrieval-eval).
- **Hub** (`deploy/hub`): the shared Matrix homeserver every area uses to reach the owner's
  phone. Guide: [Matrix hub](https://hjewkes.github.io/titan-platform/guides/hub).

## Layout

```
packages/     the shared tiers (published to npm as @titan-design/<name>)
products/     runnable compositions of the tiers (private)
apps/         front ends composed from the tiers (private)
deploy/       deployable stacks (private): hub, the shared Matrix homeserver
templates/    the uniform per-package scaffold that scripts/new-package.mjs stamps
scripts/      new-package.mjs, dag-check-self.mjs, gen-docs-reference.mjs, gen-capabilities.mjs
site/         the documentation site (VitePress)
metrics/      the metrics registry: one titan.metrics/v1 entry per area, checked by pnpm metrics:check
.codewatch/   check.json: the DAG and fitness rules codewatch enforces
```

## The DAG

A package may import only packages in its own tier or a lower one. Never sideways across a
higher tier, never upward. Tier 0 holds primitives and shared wire contracts, tier 1 engines,
tier 2 domain modules, and `ui` React bindings for the daemon wire. Every package versions
independently through changesets.

The per-package list lives in one place: the [quick index in CAPABILITIES.md](CAPABILITIES.md#quick-index),
generated by `pnpm capabilities`. The tier of each unit is the `$tiers` map in `.codewatch/check.json`, the source of truth for the `package-layers`
rule; CI fails any pull request that adds an import against the order. `deploy/hub` is a
workspace member outside that rule: it holds scripts and compose files, not library code.

## Working here

```
pnpm install && pnpm build && pnpm typecheck && pnpm lint && pnpm test && pnpm dag:check && pnpm docs:build
```

Before adding code:

1. Read [CAPABILITIES.md](CAPABILITIES.md) and the reference page of every unit that looks close.
2. Name the existing unit you reuse, or the gap you fill and its task, in the plan and the PR.
3. Verify runtime and auth assumptions with the path's smoke check before you build on them.

All six must be green before you finish a change. `dag:check` runs the self-hosted DAG
check and then the dead-export check against this repo's own `@titan-design/code-graph`,
built by `pnpm build`: the same two checks as CI's `dag-check` job.

Adding a package, running the DAG check against a base ref, the changeset requirement, the
release flow, and the docs-site scripts are all documented in
[Working in the repo](https://hjewkes.github.io/titan-platform/guides/contributing).
